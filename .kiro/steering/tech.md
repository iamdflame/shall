# Technology

## Stack

- **TypeScript**, strict, ES2022, native ES modules
- **Node.js >= 20**
- **One runtime dependency**: the `openai` SDK

## Why only one dependency

A reviewer must be able to clone this and run it. Everything except the model
calls is built on the standard library: `node:vm` for the sandbox, `node:crypto`
for cache keys, `node:child_process` for the test runner, `process.loadEnvFile`
for configuration. Adding a runtime dependency requires justifying why the
standard library cannot do the job.

## The provider boundary

`src/shall/provider/` is the only place that knows a model vendor exists. The
compiler, oracle, attribution and reporting layers never import it directly.
Adding a second vendor must not require touching any of them — this matters
because cross-vendor readers are more independent than same-vendor ones, and
independence is the property the whole system rests on.

## Determinism

Everything except the model calls is deterministic and reproducible:

- probes are generated by a fixed cartesian walk, never by sampling
- candidates are cached by a hash of the exact question asked
- the sandbox has no clock, no network, no randomness, no host globals

A conformance report a reader cannot reproduce is not evidence.

## Verification

```
npm run build     # tsc
npm test          # 104 tests, TAP
npm run verify    # this repository against .kiro/specs — 25/25
shall lint <f>    # open wording, no model calls, no API key
```

## Constraints

- Candidate code is untrusted. It runs in a fresh `node:vm` context with a
  wall-clock timeout and no access to the host environment.
- Terminal output must stay legible with `NO_COLOR=1`.
- Any cached artifact that cannot be read is recomputed, never fatal.
