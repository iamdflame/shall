Demo production guide

Shooting the SHALL demo

Everything needed to produce a three-minute submission video: the exact words to narrate, the voice and settings to generate them with, what to type on screen, and how to cut it together. Follow it top to bottom.

Length
3:00 max
Scenes

1 Get the machine ready

Do all of this before you record anything. A demo that has to stop and install something is a demo you shoot twice.

Make a clean terminal

The recording is mostly terminal, so the terminal has to look good. Big text, no clutter, nothing personal on screen.

  1. Open your terminal. Press Ctrl+Shift++ about six times to make the text large. Text that looks slightly too big on your monitor is the right size on a judge's phone.
  2. Resize the window to roughly half your screen, in the middle. Don't fullscreen it — you want a clean margin around the edge.
  3. Hide anything private: close other tabs, sign out of notifications, and turn on Do Not Disturb.
  4. Make the prompt short so it doesn't eat the line. Paste this in and press Enter: 
    export PS1="[38;5;71m$ [0m"
    Your prompt is now just a green $.

Install the shall command

Typing shall check ... on camera looks far better than node dist/shall/cli.js check .... This puts it on your PATH and needs no sudo. 

cd ~/Pictures/rya
npm run build
npm run install-cli

Check it worked. You should see the help text:

shall help
Do not use npm link. On most Linux installs it writes to a system folder and fails with a permissions error. npm run install-cli writes a small wrapper into ~/.local/bin instead, which is already on your PATH.

Silence your terminal's startup errors

Your ~/.profile currently points at a dfx install that is no longer there, so every new terminal prints two red errors. They would appear at the top of your recording. This guards those lines so they only run if the files exist: 

sed -i 's|^\. "$HOME/.local/share/dfx/env"$|[ -f "$HOME/.local/share/dfx/env" ] \&\& . "$HOME/.local/share/dfx/env"|' ~/.profile
sed -i 's|^\. "$XDG_DATA_HOME/dfx/env"$|[ -n "$XDG_DATA_HOME" ] \&\& [ -f "$XDG_DATA_HOME/dfx/env" ] \&\& . "$XDG_DATA_HOME/dfx/env"|' ~/.profile

Then close the terminal and open a new one. It should start clean.

Warm everything up

Run each command once now. The first run of anything is always slower, and you don't want that in the take. 

# in the shall folder
cd ~/Pictures/rya
npm test
npm run findings
npm run verify
shall check examples/word-count.shall
Everything below runs with no API key. The bundled examples replay from committed recordings. If you have your key in .env that's fine — but nothing in this video needs it, and that is itself worth saying out loud.

2 The narration script

Below is every word, split into seven takes. Generate each take as its own audio file — that makes editing far easier than one long file, and lets you re-do a single line without re-doing everything.

Read this before generating. Do not add words. Every number in this script is real and checked. If you improvise a bigger number, the demo stops being true, and the rules disqualify submissions whose demo doesn't match the project.
VO-10:00 – 0:20 The problem

Here is a specification. Two sentences. Count the words in the text. Ignore words shorter than three letters. Read it again. It looks completely clear. It isn't.

On screen: the file examples/word-count.shall open in your editor, nothing else. Slowly scroll so both requirements are visible.

VO-20:20 – 0:52 The split

SHALL is a language whose source code is English. It compiles this specification six times, using six different models, from GPT four-oh through GPT five point six. Each one is asked the identical question. None of them is told the others exist. Then every program they wrote is executed against the same inputs, and the results are compared. They did not write the same program. They wrote three different ones.

On screen: type shall check examples/word-count.shall and let the report print. It takes under two seconds.

VO-30:52 – 1:22 The witness

Here is the disagreement, shrunk to the smallest input that still causes it. One dash, between two letters. Four readers say five words. Two say two words. Nothing in the specification says whether a hyphen separates words — so the compiler underlines the word "words", and refuses to build.

On screen: hold on the report. Zoom slowly into the underlined ~~~~~ and the WITNESS text = "a-a" line.

VO-41:22 – 1:50 The fix

Now the same specification, with one sentence rewritten to say exactly what a token is. Six readers. Thirty-three inputs. One behaviour. It compiles. And every clause is then checked against test cases derived from that clause alone, because agreement is not the same thing as correctness.

On screen: show the one-line diff, then run shall check examples/word-count.fixed.shall. Hold on UNAMBIGUOUS and the CONFORMANCE 100% line.

VO-51:50 – 2:14 Kiro

This repository is held to the same standard it enforces. Fifty acceptance criteria, across four Kiro specs, each one bound to the code that implements it and the test that proves it. One command checks all of them. SHALL verifies itself.

On screen: briefly show the .kiro/ folder tree, then run npm run verify and hold on 50/50 criteria proven.

VO-62:14 – 2:46 The findings

Every finding here is reproducible. No API key, no spending, ten seconds. Including the one that changed the design. Five models from the same family all called a specification unambiguous — while two of them wrote comments in their own code showing they had noticed the ambiguity, and quietly picked a side. An ensemble of one family shares its blind spots.

On screen: npm run findings. Speed the middle up in editing; hold on Finding 1 and the two amber comment lines.

VO-72:46 – 3:00 Close

Requirements are the program. When independent readers disagree about what your English means, that is a compile error. SHALL.

On screen: the project name, the GitHub URL, and github.com/iamdflame/shall held for three seconds.

3 ElevenLabs — voice and settings

Which voice

Pick a calm, measured, slightly formal voice. This is a result being reported, not a product being sold — an excited startup-ad voice will actively hurt you.

VoiceWhyUse when
DanielBritish, news-presenter delivery. Authoritative and very clear on technical words.First choice. Best match for the tone.
BrianDeep, calm American. Warmer than Daniel, equally steady.If Daniel sounds too stiff to you.
GeorgeBritish, warm and conversational.If you want it friendlier.
Adam / AntoniCommon defaults — used in thousands of demos.Avoid. Judges have heard them today already.

Generating the seven files

  1. Paste VO-1 only into the text box. Nothing else.
  2. Press Generate. Listen to the whole thing.
  3. If a word sounds wrong, fix it phonetically in the text and regenerate. Useful ones for this script: 
    GPT four-oh          not "GPT 4o"
GPT five point six   not "GPT 5.6"
SHALL                if it whispers it, write S-H-A-L-L
  4. Download as MP3. Name it exactly vo-1.mp3.
  5. Repeat for VO-2 through VO-7. Keep the same voice and settings for all seven, or they won't sound like one person.
Free-tier characters. This whole script is roughly 1,600 characters. The free tier is usually 10,000 per month, so you have room for about six full regenerations. Generate one take at a time rather than the whole script repeatedly.

4 Record the screen

Install OBS

sudo apt update
sudo apt install obs-studio

Set OBS up once

  1. Open OBS. If a setup wizard appears, choose “Optimise just for recording”.
  2. In the Sources box at the bottom, click + → Screen Capture (XSHM) → OK → OK.
  3. Go to Settings → Video: 
    Base resolution:   1920x1080
Output resolution: 1920x1080
FPS:               30
  4. Go to Settings → Output: 
    Recording format:  MP4
Recording quality: High Quality, Medium File Size
  5. Settings → Audio → turn every microphone OFF. You are narrating with ElevenLabs; a live mic will only add room noise.
  6. Click OK.

Shoot each scene separately

Record seven short clips, not one long take. If you fumble a command you re-shoot ten seconds, not three minutes.

ClipWhat to doReal duration
clip-1Editor showing examples/word-count.shall. Scroll slowly once.~15 s
clip-2Terminal. Type shall check examples/word-count.shall, Enter, let it finish.~10 s
clip-3Same output still on screen. Don't type. Just let it sit.~20 s
clip-4git diff of the fixed file, then shall check examples/word-count.fixed.shall.~15 s
clip-5tree .kiro then npm run verify.~25 s
clip-6npm run findings. Runs about 70 s — you will speed this up later.~70 s
clip-7A plain terminal showing the repo URL, or a simple title card.~8 s

Type commands at a normal, unhurried pace. Do not backspace on camera — if you mistype, stop the recording and shoot that clip again.

The exact commands, ready to copy.

5 Edit it together

Install Kdenlive

sudo apt install kdenlive

Assemble

  1. Open Kdenlive → Project → Add Clip → select all seven video clips and all seven MP3s.
  2. Drag clip-1 onto the V1 video track at the very start. Drag vo-1.mp3 onto the A1 audio track, also at the start.
  3. Repeat in order: each clip on V1, its voiceover on A1, butted up against the previous one with no gaps.
  4. Match the video to the voice, not the reverse. If VO-3 runs 30 seconds and clip-3 is only 20, stretch clip-3: right-click → Duration → set it to match. A still terminal held longer is fine.

Speed up the slow bit

Clip-6 (npm run findings) runs about 70 seconds and the voiceover is 32. Right-click the clip → Change Speed → set 300 %. Then cut the last few seconds so it ends on the green “all findings reproduced” line.

Make it readable

  • Add a Zoom effect on clip-3 slowly pushing into the underlined word. Effects → search “Transform” → animate Size from 100 % to 140 %.
  • Add a half-second black fade at the very start and very end (Transitions → Fade from black / Fade to black).
  • Put a title card on clip-7: Project → Add Title Clip. Two lines only — SHALL and github.com/iamdflame/shall.
  • No background music. It competes with the narration and adds nothing here.

Export

  1. Click Render (top toolbar).
  2. Choose MP4 – H.264/AAC.
  3. Set the file name to shall-demo.mp4.
  4. Click Render to File. Wait.
  5. Watch the whole thing back before uploading. All of it.

6 Upload and submit

  1. Go to YouTube → Create → Upload video.
  2. Title: SHALL — a language whose source code is English
  3. Description: paste the first paragraph of the README plus the repo link.
  4. Visibility: Unlisted is accepted and is the safer choice.
  5. Copy the link into the submission form alongside github.com/iamdflame/shall.

7 Final checks

  • The repository is public — a judge in a private window can open it.
  • The video is under 3:00.
  • Every number spoken matches what is on screen.
  • No API key, no .env, and no personal information is visible in any frame.
  • The .kiro folder appears on screen during VO-5.
  • Audio is audible on phone speakers — test it on your phone, not your laptop.
  • The README, the video and the repository all tell the same story.
If you only have time for one improvement. Re-record clip-3 and hold longer on the witness. The single most persuasive moment in the whole video is a viewer realising that "a-a" — three characters — is enough to split six state-of-the-art models. Give that time to land.
Every command and duration in this guide was measured on the actual project. shall check takes 1.7 s, npm run verify 16 s, npm run findings 67 s.
